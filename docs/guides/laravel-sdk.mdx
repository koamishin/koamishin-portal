# Laravel SDK integration

The PHP SDK connects a Laravel application to Koamishin Portal using OAuth 2.0 authorization code with PKCE. It includes a Laravel authentication guard, a server-side management client, and webhook verification. The SDK source in this repository may be newer than the published Composer package; install a version that contains these features before following this guide. See the [package README](../../packages/koamishin-auth-php/README.md) for the complete reference and supported dependency ranges.

## 1. Prepare the Portal

Create an organization and a Laravel application in the Portal. Register the exact callback URL used by your Laravel application and save the displayed authorization-code client ID and secret. Enroll a test user in both the organization and this application environment. Development and production use separate clients and memberships. The other environment's callback list starts empty. See [tenancy and OAuth](core-concepts.mdx).

Deploy a Portal release that includes the scoped API described here. Record the Portal application ID and environment; the SDK checks both against each userinfo response to prevent a token for another application from authenticating to yours.

## 2. Install and configure the SDK

In the consuming Laravel project, install the appropriate SDK release and publish its configuration:

```bash
composer require koamishin/auth-php
php artisan vendor:publish --tag=koamishin-config --no-interaction
```

Until a tagged release containing these features is published, a normal stable install may select an older version. For development, once the updated GitHub branch is available, you can configure the consuming project to use it explicitly:

```bash
composer config repositories.koamishin-auth vcs https://github.com/koamishin/auth-php.git
composer require koamishin/auth-php:dev-main
```

Commit that project's Composer lockfile to pin the resolved revision; use a reviewed release for production.

Set these values in the consuming application's `.env`, using the authorization-code client for the selected environment:

```dotenv
KOAMISHIN_PORTAL_URL=https://auth.example.com
KOAMISHIN_CLIENT_ID=your-authorization-client-id
KOAMISHIN_CLIENT_SECRET=your-authorization-client-secret
KOAMISHIN_REDIRECT_URI=https://app.example.com/koamishin/callback
KOAMISHIN_APPLICATION_ID=42
KOAMISHIN_ENVIRONMENT=production
```

Keep secrets server-side. The SDK requires matching application and environment claims; a missing or mismatched configuration fails authentication. Use HTTPS and secure Laravel session cookies in production. The SDK stores encrypted tokens in the session, so protect both session storage and `APP_KEY`. Rebuild the Laravel configuration cache after changing environment values.

Add a guard in the consuming application's `config/auth.php`:

```php
'guards' => [
    // Keep any other guards your application uses.
    'koamishin' => [
        'driver' => 'koamishin',
    ],
],
```

## 3. Add login and protected routes

Add the following routes to `routes/web.php`. The web middleware and session must be active. The callback URL must exactly match the one registered in the Portal.

```php
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Route;
use Koamishin\Auth\Facades\Koamishin;

Route::get('/login', fn () => redirect()->away(
    Koamishin::getLoginUrl('/dashboard')
))->name('login');

Route::get('/koamishin/callback', function (Request $request) {
    if ($request->query('error')) {
        abort(403, 'Sign-in was not completed.');
    }

    $input = $request->validate([
        'code' => ['required', 'string'],
        'state' => ['required', 'string'],
    ]);

    try {
        Koamishin::handleCallback($input['code'], $input['state']);
    } catch (InvalidArgumentException $exception) {
        abort(403, 'Invalid or expired sign-in request.');
    }

    return redirect()->to(Koamishin::consumeReturnTo('/dashboard'));
});

Route::get('/dashboard', function (Request $request) {
    $user = $request->user();

    return response()->json([
        'id' => $user->id,
        'name' => $user->name,
        'public_metadata' => $user->publicMetadata,
    ]);
})->middleware('auth:koamishin');

Route::post('/logout', function () {
    Koamishin::logout();

    return redirect('/');
})->name('logout');
```

Submit logout using a POST form with `@csrf`. The SDK validates the OAuth state, exchanges the authorization code, rotates the local session ID, and revalidates the user's access token with the Portal for authenticated requests. It can refresh expired access tokens. If the Portal is unavailable, authentication can fail; plan for this dependency. Local logout clears the consuming application's Koamishin session; it does not revoke the Portal token or end the Portal's own browser session.

The guard returns a `KoamishinUser`, not an Eloquent model. Map its ID to a local model if required by your app. For bearer-token requests the guard validates the token against the Portal, and an invalid bearer token does not fall back to a browser session. Use session blocking with a shared lock-capable cache when concurrent requests can refresh the same session. For role checks and additional guard details, see the [SDK README](../../packages/koamishin-auth-php/README.md).

## 4. Manage users and metadata from the server

Create a separate management credential on the Portal host. Give it only the scopes your server needs. For example:

```bash
php artisan koamishin:management-client 42 production \
  --scope=users:read --scope=metadata:read --scope=metadata:write \
  --scope=sessions:read --scope=sessions:revoke \
  --scope=memberships:write --scope=organization:read \
  --no-interaction
```

Save the shown secret and configure the consuming server:

```dotenv
KOAMISHIN_MANAGEMENT_CLIENT_ID=your-management-client-id
KOAMISHIN_MANAGEMENT_CLIENT_SECRET=your-management-client-secret
```

```php
use Koamishin\Auth\KoamishinManagementClient;

$portal = app(KoamishinManagementClient::class);
$users = $portal->listUsers(page: 1, perPage: 25);
// Existing organization members can be enrolled into this environment:
$portal->enrollUserInApplication('42');
$user = $portal->getUser('42');
$metadata = $portal->updateUserMetadata(
    $user->id,
    public: ['theme' => 'dark'],
    private: ['customer_id' => 'C-123'],
);

$sessions = $portal->listUserSessions($user->id);
if ($sessions['data'] !== []) {
    $portal->revokeUserSession($user->id, $sessions['data'][0]['id']);
}
```

These operations apply only to the credential's application environment. A session here is an OAuth grant: revocation targets the selected access/refresh token pair, not all Portal browser sessions or other applications. Refreshing a grant changes its ID, and a refresh concurrent with revocation can race; list again and handle a stale ID. See [application user metadata](user-metadata.mdx) for replacement semantics and privacy, and [API reference](../reference/examples.mdx) for scopes and membership operations.

## 5. Receive webhooks

Create an endpoint in the Portal for this application environment and subscribe to the desired user events. Keep the signing secret on the receiving server, and set `KOAMISHIN_WEBHOOK_FORMAT` to the same `legacy` or `standard` format selected in the Portal.

The [package README](../../packages/koamishin-auth-php/README.md#verify-and-process-webhooks) contains a complete route that validates the raw body and signature and uses the optional replay processor. Use a persistent shared cache with atomic locks and make side effects idempotent; the helper reduces duplicate processing but cannot guarantee exactly-once effects. Start the Portal's queue worker and check delivery records when testing.

## Troubleshooting

- **Login is denied:** Check that the callback matches, the OAuth client is active and uniquely mapped, and the user is enrolled in the organization and correct application environment. Verify the SDK's expected application ID and environment.
- **Management returns 403 or 404:** Confirm that the management credential belongs to the target environment, has the required scopes, and the user is enrolled there.
- **Webhook signature fails:** Check the secret, format, original body, headers, and clock synchronization. Confirm the endpoint is assigned to the correct environment and its queue worker is running.
- **Package method or configuration is missing:** Verify the installed Composer version contains this guide's changes; the repository source can be newer than a published package.

The Portal does not issue OIDC ID tokens or provide complete OpenID Connect conformance. Do not use it as an OIDC-only identity provider.
