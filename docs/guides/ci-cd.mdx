# Production Deployment & Operations

This guide covers deploying Koamishin Portal to production environments with high availability, secure secret management, background queue workers, and automated release strategies.

---

## Production Architecture Overview

```
                                  +-------------------------------------------+
                                  |         Internet (HTTPS / TLS 443)        |
                                  +-------------------------------------------+
                                                        |
                                                        v
                                  +-------------------------------------------+
                                  |   Reverse Proxy (Nginx / Caddy / Cloud)   |
                                  |          SSL/TLS Termination              |
                                  +-------------------------------------------+
                                                        |
                                +-----------------------+-----------------------+
                                |                                               |
                                v                                               v
                 +-----------------------------+                 +-----------------------------+
                 |   Koamishin Web / Octane    |                 |   Background Queue Worker   |
                 |     FrankenPHP / PHP-FPM    |                 |    (Supervisor / Systemd)   |
                 +-----------------------------+                 +-----------------------------+
                                |                                               |
                                +-----------------------+-----------------------+
                                                        |
                                                        v
                                +-----------------------------------------------+
                                |               Data & Cache Tier               |
                                |     - PostgreSQL 17 (Primary Database)        |
                                |     - Redis 7+ (Sessions, Cache, Queues)      |
                                |     - Persistent Volume (OAuth RSA Keys)      |
                                +-----------------------------------------------+
```

## Deployment Option A: Docker Compose (Production Stack)

The bundled container architecture is based on **Laravel Octane (FrankenPHP)**, providing multi-worker concurrency with minimal memory overhead.

### 1. Production Docker Compose Configuration

Create a dedicated `docker-compose.prod.yml` on your server:

```yaml
services:
    portal:
        image: ghcr.io/koamishin/koamishin-portal:latest
        restart: unless-stopped
        ports:
            - '127.0.0.1:8000:8000'
        env_file: .env.production
        volumes:
            - portal_storage:/app/storage
        depends_on:
            pgsql:
                condition: service_healthy
            redis:
                condition: service_healthy

    queue:
        image: ghcr.io/koamishin/koamishin-portal:latest
        restart: unless-stopped
        command: php artisan queue:work redis --sleep=3 --tries=3 --timeout=60 --no-interaction
        env_file: .env.production
        volumes:
            - portal_storage:/app/storage
        depends_on:
            pgsql:
                condition: service_healthy
            redis:
                condition: service_healthy

    pgsql:
        image: postgres:17-alpine
        restart: unless-stopped
        environment:
            POSTGRES_DB: koamishin_portal
            POSTGRES_USER: ${DB_USERNAME}
            POSTGRES_PASSWORD: ${DB_PASSWORD}
        volumes:
            - pgsql_data:/var/lib/postgresql/data
        healthcheck:
            test:
                [
                    'CMD-SHELL',
                    'pg_isready -U ${DB_USERNAME} -d koamishin_portal',
                ]
            interval: 5s
            timeout: 5s
            retries: 5

    redis:
        image: redis:7-alpine
        restart: unless-stopped
        command: redis-server --appendonly yes --requirepass ${REDIS_PASSWORD}
        volumes:
            - redis_data:/data
        healthcheck:
            test: ['CMD', 'redis-cli', '-a', '${REDIS_PASSWORD}', 'ping']
            interval: 5s
            timeout: 5s
            retries: 5

volumes:
    portal_storage:
    pgsql_data:
    redis_data:
```

### 2. Production Environment File (`.env.production`)

```dotenv
APP_NAME="Koamishin Portal"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://auth.example.com

# Key must be generated once and kept stable
APP_KEY=base64:YOUR_GENERATED_32_BYTE_BASE64_KEY

# Database
DB_CONNECTION=pgsql
DB_HOST=pgsql
DB_PORT=5432
DB_DATABASE=koamishin_portal
DB_USERNAME=portal_user
DB_PASSWORD=YOUR_STRONG_POSTGRES_PASSWORD

# Redis & Queues
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=YOUR_STRONG_REDIS_PASSWORD

QUEUE_CONNECTION=redis
SESSION_DRIVER=redis
CACHE_STORE=redis

# Production Mail
MAIL_MAILER=smtp
MAIL_HOST=smtp.sendgrid.net
MAIL_PORT=587
MAIL_USERNAME=apikey
MAIL_PASSWORD=YOUR_SENDGRID_OR_RESEND_API_KEY
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=auth@example.com
MAIL_FROM_NAME="Koamishin Identity"

# Session Security
SESSION_ENCRYPT=true
SESSION_PATH=/
SESSION_DOMAIN=.example.com
```

### 3. Deploy and Initialize

```bash
# 1. Start database and cache
docker compose -f docker-compose.prod.yml up -d pgsql redis

# 2. Run migrations
docker compose -f docker-compose.prod.yml run --rm portal php artisan migrate --force --no-interaction
docker compose -f docker-compose.prod.yml run --rm portal php artisan module:migrate --all --force --no-interaction

# 3. Generate OAuth RSA keys inside persistent volume (RUN ONCE)
docker compose -f docker-compose.prod.yml run --rm portal php artisan passport:keys --no-interaction

# 4. Start portal and queue workers
docker compose -f docker-compose.prod.yml up -d portal queue
```

## Deployment Option B: Ubuntu / Debian Linux Host (Nginx + PHP-FPM)

For traditional VPS environments (AWS EC2, DigitalOcean, Hetzner, Linode):

### 1. Install System Dependencies

```bash
sudo apt update && sudo apt install -y \
  nginx \
  php8.5-fpm \
  php8.5-pgsql \
  php8.5-redis \
  php8.5-mbstring \
  php8.5-xml \
  php8.5-bcmath \
  php8.5-curl \
  php8.5-zip \
  php8.5-pcntl \
  supervisor \
  certbot \
  python3-certbot-nginx
```

### 2. Configure Nginx Virtual Host

Create `/etc/nginx/sites-available/koamishin-portal.conf`:

```nginx
server {
    listen 80;
    server_name auth.example.com;
    root /var/www/koamishin-portal/public;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header Referrer-Policy "strict-origin-when-cross-origin";

    index index.php;
    charset utf-8;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { access_log off; log_not_found off; }

    error_page 404 /index.php;

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.5-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_hide_header X-Powered-By;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}
```

Enable the site and obtain a free Let's Encrypt SSL certificate:

```bash
sudo ln -s /etc/nginx/sites-available/koamishin-portal.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d auth.example.com
```

### 3. Configure Background Queue Supervisor

Create `/etc/supervisor/conf.d/koamishin-worker.conf`:

```ini
[program:koamishin-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/koamishin-portal/artisan queue:work redis --sleep=3 --tries=3 --timeout=60 --no-interaction
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/log/supervisor/koamishin-worker.log
stopwaitsecs=3600
```

Load and start the worker processes:

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start koamishin-worker:*
```

## Zero-Downtime Release Sequence

When deploying application updates, run the following command sequence to ensure zero disruption and clear caches safely:

```bash
cd /var/www/koamishin-portal

# 1. Pull latest release or checkout new release directory
git pull origin main

# 2. Install production dependencies
composer install --no-dev --optimize-autoloader --no-interaction
npm ci
npm run build

# 3. Put portal in maintenance mode (optional, skips if using atomic symlink)
php artisan down --render="errors::503"

# 4. Run database migrations
php artisan migrate --force --no-interaction
php artisan module:migrate --all --force --no-interaction

# 5. Clear and rebuild compiled caches
php artisan optimize:clear --no-interaction
php artisan config:cache --no-interaction
php artisan route:cache --no-interaction
php artisan view:cache --no-interaction
php artisan event:cache --no-interaction

# 6. Gracefully restart queue workers
php artisan queue:restart --no-interaction

# 7. Bring portal back online
php artisan up
```

## Critical Production Safeguards

### 1. Persistent Storage & Encryption Keys

The following files and paths must **never** be deleted or regenerated during updates:

| Path                        | Purpose                                          | Recovery Requirement                                             |
| :-------------------------- | :----------------------------------------------- | :--------------------------------------------------------------- |
| `storage/oauth-private.key` | Signs RS256 JWT access and identity tokens       | If lost, all active client sessions and tokens are invalidated.  |
| `storage/oauth-public.key`  | Verifies JWT signatures via `/oauth/jwks`        | Must match `oauth-private.key`.                                  |
| `.env` (`APP_KEY`)          | Encrypts database cookies, sessions, and secrets | If changed, all encrypted user fields and session cookies break. |
| `storage/app/public`        | User avatars, custom logos, and uploads          | Must be backed up and symlinked to `public/storage`.             |

### 2. Restricting the `/setup` Wizard

The `/setup` interactive wizard is active **only when no user has the `super_admin` role**.

- Once your super administrator account is created, `/setup` automatically responds with a redirect to the home page or dashboard.
- **Auditing**: Ensure at least one active account retains the `super_admin` role. If you revoke all `super_admin` roles, the setup wizard will reopen to public visitors.

### 3. Automated Database Backups

Schedule regular automated PostgreSQL backups using cron:

```bash
# Add to /etc/cron.daily/backup-koamishin
#!/bin/bash
BACKUP_DIR="/var/backups/koamishin"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
mkdir -p "$BACKUP_DIR"

# Dump database
pg_dump -U portal_user -h localhost koamishin_portal | gzip > "$BACKUP_DIR/db_$TIMESTAMP.sql.gz"

# Retain last 14 days
find "$BACKUP_DIR" -type f -mtime +14 -name "*.sql.gz" -exec rm {} +
```

## Healthchecks & Monitoring

Koamishin Portal provides standard monitoring endpoints:

- **HTTP Status Check**: `GET /up`
  Returns HTTP 200 `OK` when the Laravel kernel boots successfully. Ideal for AWS ALB, Kubernetes liveness probes, or Cloudflare health monitors.
- **OIDC Discovery**: `GET /.well-known/openid-configuration`
  Returns RFC-compliant OpenID Connect discovery metadata.
- **JWKS Endpoint**: `GET /oauth/jwks`
  Exposes the public RS256 key set.
