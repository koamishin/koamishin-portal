# Astro landing

The `landing/` directory is a separate static Astro site. It also publishes the repository's documentation at `/docs/`, using the files in `docs/` as its source. The development dependency [Laravel Astro Landing](https://github.com/lauroguedes/laravel-astro-landing) provides the Artisan commands used below. The Laravel application continues to serve its own `/` route; deploying the landing does not change it. The landing and the application can use separate domains, for example `www.example.com` and `auth.example.com`.

## Local development

Install the root Composer dependencies, including development dependencies, and the landing's locked npm dependencies. Use a Node version supported by `landing/package.json` and its lockfile.

```bash
composer install
npm ci --prefix landing
test -f landing/.env || cp landing/.env.example landing/.env
php artisan landing:dev --no-interaction
```

The server prints its local address, normally `http://localhost:4321`. Run Laravel separately as described in [local development](../getting-started/local-development.mdx). Set `PUBLIC_APP_URL` in `landing/.env` to the Laravel application's origin, including its port. It defaults to `http://localhost:8000`; the sign-in links append `/login`. The landing's `.env` is separate from Laravel's `.env`.

## Build and deploy

Build from a complete checkout: the landing reads selected files from `docs/`, the root contribution and project guidance, and the SDK packages. The explicit source list lives in `landing/src/lib/docs.mjs`; add new public documentation and linked files there before publishing them. The current renderer supports Markdown syntax in these `.mdx` files, including fenced code and tables, but does not execute MDX components or expressions. Set `PUBLIC_APP_URL` to the public HTTPS origin of your deployed Laravel application **at build time**. Astro embeds it into the static output; changing a server environment variable after the build does not update existing files. This value is public and must not contain a secret.

```bash
npm ci --prefix landing
PUBLIC_APP_URL=https://auth.example.com php artisan landing:build --no-interaction
```

Upload the contents of `landing/dist/` to a static hosting service configured to serve `index.html` for directories, including nested paths such as `/docs/guides/landing/`. Deploy the entire output so the documentation pages and their assets are available alongside the landing page. Check that `/docs/` and a nested guide load directly as well as through navigation. Configure the landing's domain and HTTPS with that provider. Set the actual application origin in the command above, rebuild for each environment, and check the deployed sign-in link before directing users to it. The example address is a placeholder. The current site uses root-relative links and is intended for hosting at the domain root. Hosting under a path requires updating those links and Astro's `base` before deployment.

The package is a Composer development dependency, so `landing:build` is available where development dependencies are installed, such as a build machine or CI. Alternatively, build from the landing directory with `npm run build` after installing its dependencies and setting the same `PUBLIC_APP_URL`. The resulting static files do not need PHP. The package can generate provider-specific workflows with `php artisan landing:workflow --help`; review the generated workflow, include changes to the documentation source paths in its build triggers, and configure the provider's credentials before enabling it. No landing deployment workflow is configured by default in this repository.

Deploy and operate the Laravel application independently using [deployment and operations](ci-cd.mdx). Before production, address the documented authentication and container limitations there and in [tenancy and OAuth](core-concepts.mdx).
